**AB05 is the ISO 20022 reason code "Timeout Creditor Agent".** The transaction was stopped because of a timeout at the creditor's bank, meaning the bank of whoever is collecting the money. It's a technical or processing failure, not a problem with the payer's account (no insufficient funds, closed account, or revoked mandate).

**When can you debit again?**
- Usually right away. A technical timeout has no mandatory waiting period, unlike a return for a reason like insufficient funds.
- Submit it as a new collection with a new message and instruction ID. Don't resend the identical file, because duplicate IDs can cause another rejection.
- Set a new valid collection date. For SEPA Core, submission deadlines are typically D-1 for both first and recurring debits, but your bank may require earlier cutoffs.
- Your existing mandate stays valid, so you don't need a new one. Mandates lapse only after 36 months without use.
- If this was a first-time debit, check that the mandate data was transmitted correctly.

If AB05 keeps recurring, ask your bank or payment provider whether there's a connectivity or processing problem on their side. They can see more detail than the code alone.

I'm going from the standard ISO 20022 code list. Banks sometimes attach their own text to a code, so check the return message or your bank's documentation if anything differs.
